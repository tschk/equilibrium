# FFI audit

This audit describes equilibrium at `206b4b67ddcc17a969d8b54442e41ae88617c265`. It is a source review, not a complete ABI certification or a claim about later branches. The priorities below reflect potential consequences, not measured frequency.

Since this snapshot, binding generation has been hardened against several incomplete aggregate layouts and their by-value uses. This does not cover all layout-affecting syntax: packed attributes and packing directives still need target-aware handling. Some unsupported array and pointer typedefs are rejected instead of generating an ABI declaration.

## Priorities

1. **Prevent partial aggregate layouts.** [`generate_struct` and `generate_union`](../src/bindings.rs) warn and continue when an ordinary field has an invalid name or unsupported type. The resulting definition can have the wrong size, alignment, or offsets. [`parse_typedef_struct`](../src/c_header.rs) can also omit fields that it cannot parse before generation sees them. Unsupported bitfield layouts have a separate rejection path, but that does not protect ordinary fields. Reject the whole aggregate when any field is lost, propagate that failure to by-value users, and test both parser and emitter failures against C layout probes.
2. **Represent C enums without Rust enum validity assumptions.** [`generate_enum`](../src/bindings.rs) emits a `#[repr(C)]` Rust enum. C can pass an integer value not listed among its enumerators, which is not a valid Rust enum value. C also permits aliases with the same value, while duplicate Rust discriminants fail to compile. Use an integer-backed representation and constants, with the underlying type determined for the target ABI. Test aliases, unknown values, and target-dependent enum sizes.
3. **Make missing declarations visible.** [`parse_c_header`](../src/c_header.rs) reads raw lines rather than preprocessing conditional branches or resolving includes. `BindingOptions::include_paths` is declared in [`bindings.rs`](../src/bindings.rs) but is not used by its generation path. Function parsing is line-based; `test_generate_bindings_skips_multiline_prototype` documents a skipped multiline prototype. Consequently, successful generation does not establish that a header was interpreted as the compiler sees it. Add target-aware preprocessing and parsing with explicit include paths, defines, and target options, and report declarations that cannot be represented.
4. **Close allowlist dependencies.** [`emit_bindings_from_parsed`](../src/bindings.rs) filters functions and types independently by exact name. A selected function or aggregate can reference a type that the type allowlist excludes. Compute the transitive type dependencies of selected declarations, or return a diagnostic naming each missing dependency. Test generated code compilation as well as the selected symbols.

## Implementation opportunities

- Compare generated size, alignment, and field offsets with compiled C probes on each supported target and compiler configuration. Cross-compilation needs target-derived layout information rather than the host layout. Probes establish coverage for tested cases, not all headers.
- Replace unstructured warning strings with diagnostics that identify the declaration, source location when available, reason, and severity. Offer strict generation that fails on ABI-relevant omissions. Preserve a clearly identified permissive mode if callers need partial output.
- Model capabilities separately for source language, runtime, and ABI direction. A TypeScript syntax choice does not imply that scriptc, Node, or another runtime has the same transport or supported types. Record target and marshalling constraints in the capability result instead of treating language detection as proof of interoperability.
- Compose scriptc manifests as typed data before serialization. [`scriptc_manifest`](../src/imports.rs) currently builds JSON text for one generated import. Typed composition can validate duplicate symbols, library paths, and incompatible signatures across dependencies before writing a combined manifest. The need for shared composition is a design opportunity, not evidence of a present collision.

## Ownership and consumer failure boundaries

These are distinct contracts, not interchangeable TypeScript FFI conventions. The examples describe generated code at the cited revisions. They do not establish that every transport or arbitrary native library follows the same rules.

The [cross-family FFI ownership contract](FFI-OWNERSHIP-PROPOSAL.md) is a proposal for future adapters, not an existing interoperability guarantee.

**A pointer crossing these boundaries does not carry its ownership or lifetime with it.** Treating an archive-owned result as an eqts-owned buffer, retaining callback bytes after return, or passing an invalid borrowed span to rig can cause use-after-free, invalid frees, undefined behavior, or a crash in the consumer process. The projects do not expose one shared ownership contract; adapters must preserve each producer's documented rules rather than infer them from a C pointer.

- **equilibrium's scriptc library producer.** The current [`header`](../src/scriptc.rs) output says that the archive owns buffered results until the module's `collect` function is called. Consumers must not treat those results as independently owned allocations or use them after collection. The same header says to initialize the module before calling exports and that an unregistered trap aborts the process. Registering a panic sink receives trap messages; the header does not promise recovery from every trap. These current-source observations are separate from the audit snapshot above.
- **rig's borrowed inputs.** At `018f6d8`, [`api_scan.rs`](https://github.com/tschk/rig/blob/018f6d8a7b9c400d88033537ffad46b173aa96c9/src/expose/api_scan.rs) expands shared `&str` and `&[u8]` parameters into pointer-length pairs. The generated [surface wrapper](https://github.com/tschk/rig/blob/018f6d8a7b9c400d88033537ffad46b173aa96c9/src/expose/surface.rs) constructs borrowed Rust slices for the call, checks null with nonzero length, and checks UTF-8 for strings. Those checks cannot validate a non-null pointer's provenance or readable extent. The consumer must supply valid memory for the call; an invalid pointer or length can cause undefined behavior or crash the process. This input borrowing does not define ownership of arbitrary returned pointers.
- **eqts's owned output buffers.** At `0a2e307`, the generated [JSON ABI wrapper](https://github.com/tschk/eqts/blob/0a2e307670375b8a3c6b801304c84803c476a972/eqts-macros/src/lib.rs) returns an `OwnedBuffer` and documents the input and output pointer requirements. Its [Node, Bun, and Deno loaders](https://github.com/tschk/eqts/blob/0a2e307670375b8a3c6b801304c84803c476a972/cargo-eqts/src/main.rs) read the output and call `eqts_buffer_free_v1` in `finally` blocks. The [scriptc bridge](https://github.com/tschk/eqts/blob/0a2e307670375b8a3c6b801304c84803c476a972/cargo-eqts/src/scriptc.rs) calls the output callback before freeing the buffer, so a callback must copy bytes it needs after it returns. A retained pointer becomes invalid after that free. These buffer rules do not describe eqts scalar results or every eqts transport.
- **Failure handling is path-specific.** The eqts JSON wrapper catches unwinding Rust panics and returns a status, but that does not make invalid pointers safe or catch process aborts. The cited rig surface wrapper calls its target without a panic-catching boundary. A panic that reaches a non-unwinding `extern "C"` boundary can abort the consumer process. These are source-based risks, not reports of observed crashes.
- **eqswift delegates to UniFFI.** The cited eqswift source identifies `Record` and `Object` as UniFFI types. It does not establish that their ownership or failure handling matches either eqts or equilibrium. Check the applicable UniFFI version and generated bindings before relying on a lifetime or recovery guarantee.

## Verification gaps

Windows C# Native AOT end-to-end linking has not been verified. The existing end-to-end tests are Unix-only; passing Windows CI does not establish that this path works on Windows.
